# 기능 명세서와 범위

> 이 문서는 `model/` 의 데이터에서 자동으로 만들어집니다. 직접 고치지 말고 `model/` 을 고친 뒤 `npm run plan:build` 를 실행하세요.

MVP 기능은 5개를 넘지 않게 하네스가 막습니다(SCP-01). 무엇을 할지만큼 무엇을 하지 않을지가 중요합니다.

## MVP (5개)

| ID | 기능 | 요구사항 | 화면 | 설명 |
| --- | --- | --- | --- | --- |
| F-01 | 가게 등록 | R-01, R-06, R-09 | S-01 | 상호·대표 메뉴·특징 한 줄과 (선택) 연령대를 받아 가게 정보를 만든다. 이후 모든 문구와 할 일의 재료가 된다. |
| F-02 | 홍보 문구 만들기 | R-02 | S-02 | 등록 정보만으로 채널별 문구를 만들고 사장님이 고친다. |
| F-03 | 오늘의 할 일 1개 | R-03 | S-03 | 하루 한 번, 5분 안에 끝나는 할 일 한 개를 알려 준다. |
| F-04 | 문구 복사·공유 | R-05 | S-02 | 만든 문구를 복사하거나 공유 화면으로 넘기고, 채널별 올리는 방법을 안내한다. |
| F-05 | 실행 체크와 주간 수행률 | R-04 | S-03, S-04 | 완료·건너뜀과 건너뛴 이유를 기록하고 주간 수행률을 보여 준다. H-04 를 재는 데 꼭 필요하다. |

## 하지 않는 것

| ID | 항목 | 이유 |
| --- | --- | --- |
| N-01 | 결제·POS 연동 | 기존 강자의 영역이고 연동 비용과 계약이 필요하다. 이번 가설(P-01, P-03)을 확인하는 데 필요하지 않다. |
| N-02 | 손님 전화번호 수집과 문자 발송 | 개인정보 부담과 문자 비용이 생기고(E-01 도도포인트의 약점), 수집보다 활용이 문제라는 가설(P-03)과 맞지 않는다. |
| N-03 | 손님용 앱과 양면 시장 | 사장님 쪽 문제가 먼저 확인되어야 한다(P-05 보류). |
| N-04 | 영상·숏폼 자동 생성 | 이미 경쟁이 치열한 영역이다(E-02). 문구로 시작한다. |
| N-05 | 요식업 외 업종 확장(미용, 학원, 세탁 등) | 세그먼트마다 다른 제품이 된다(D-01). |
| N-06 | 인쇄소 연동 | 전단 생성(F-08)도 later 이다. |
| N-07 | 실제 유료 출시와 결제 처리 | 이번 프로젝트는 기획과 검증까지다(D-07). |
