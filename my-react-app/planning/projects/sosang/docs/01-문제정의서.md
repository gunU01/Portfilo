# 문제 정의서

> 이 문서는 `model/` 의 데이터에서 자동으로 만들어집니다. 직접 고치지 말고 `model/` 을 고친 뒤 `npm run plan:build` 를 실행하세요.

문제는 모두 **가설**입니다. 근거는 팀 노션 문서(2차 자료)이고, 사장님에게 직접 확인한 결과는 아직 없습니다.

## P-01 요식업 사장님은 홍보 도구가 없어서가 아니라, 도구를 쓸 시간과 판단력이 없어서 홍보를 못 한다.

| 항목 | 내용 |
| --- | --- |
| 대상 | 요식업 사장님(카페·식당) |
| 상태 | 가설(검증 전) |
| 겪는 불편 | 인스타그램·카카오 채널·스마트플레이스를 만들어 두고 방치한다. 무엇을 올릴지, 어떻게 쓸지 정하는 일이 영업 중에는 우선순위에서 밀린다. |
| 지금 쓰는 대안 | 무료 채널을 직접 운영하거나 방치, 대행사·체험단 이용, 종이 쿠폰 |
| 근거 | E-03(2차 자료), E-01(2차 자료) |

## P-02 사장님은 떠난 단골이 왜 안 오는지 궁금하지만, 알아차리거나 대응할 방법이 없다.

| 항목 | 내용 |
| --- | --- |
| 대상 | 요식업 사장님 |
| 상태 | 가설(검증 전) |
| 겪는 불편 | 단골이 줄어도 매출이 빠진 뒤에야 안다. 번호가 있어도 누구에게 무엇을 보낼지 모른다. |
| 지금 쓰는 대안 | 태블릿 적립(도도포인트류), 종이 도장, 카카오 채널 |
| 근거 | E-03(2차 자료), E-01(2차 자료) |

## P-03 단골 관리와 홍보의 병목은 데이터 수집이 아니라 '오늘 뭘 하면 되는지' 알려 주는 실행 단위가 없다는 점이다.

| 항목 | 내용 |
| --- | --- |
| 대상 | 요식업 사장님 |
| 상태 | 가설(검증 전) |
| 겪는 불편 | 해야 할 일이 크고 막연해서 미룬다. 하루 5분 안에 끝나는 크기의 할 일이 주어지지 않는다. |
| 지금 쓰는 대안 | 기존 서비스는 대시보드와 도구를 주고 사장님이 쓰기를 기대한다 |
| 근거 | E-03(2차 자료), E-01(2차 자료), E-02(2차 자료) |

## P-04 매출이 빠져도 원인(날씨, 경쟁점, 단골 이탈)을 추측만 할 뿐 진단하지 못한다.

| 항목 | 내용 |
| --- | --- |
| 대상 | 요식업 사장님 |
| 상태 | 보류 |
| 겪는 불편 | 원인을 몰라 대응 우선순위를 정하지 못한다. |
| 지금 쓰는 대안 | 매출 앱(캐시노트 등)의 통계 |
| 근거 | E-03(2차 자료) |
| 보류 이유 | 진단하려면 먼저 매출·방문 데이터가 쌓여야 한다. MVP 이후에 다룬다. |

## P-05 손님도 좋아하는 가게에 애정을 표현하고 혜택을 받을 채널이 없다(양면 시장).

| 항목 | 내용 |
| --- | --- |
| 대상 | 동네 단골 손님 |
| 상태 | 보류 |
| 겪는 불편 | 단골 혜택을 받을 접점이 가게마다 흩어져 있다. |
| 지금 쓰는 대안 | 당근·네이버 등 플랫폼의 쿠폰과 멤버십 |
| 근거 | E-03(2차 자료), E-01(2차 자료) |
| 보류 이유 | 사장님 쪽 문제가 먼저 확인되어야 한다. 손님 앱은 범위를 크게 키운다(N-03). |
