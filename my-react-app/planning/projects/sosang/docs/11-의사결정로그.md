# 의사결정 로그

> 이 문서는 `model/` 의 데이터에서 자동으로 만들어집니다. 직접 고치지 말고 `model/` 을 고친 뒤 `npm run plan:build` 를 실행하세요.

'제안(승인 대기)'은 Claude 가 문서를 바탕으로 낸 제안입니다. 문채원 님이 `model/decisions.mjs` 에서 status 를 accepted 로 바꾸기 전에는 확정으로 쓰지 않습니다.

## D-01 첫 대상을 요식업 사장님 하나로 좁힌다 — 확정

- **배경**: 노션 문서는 요식업, 예약 기반 뷰티, 학원, 생활서비스, 신규 오픈 매장까지 세그먼트마다 문제의 결이 다르다고 정리한다.
- **선택지**
  - 요식업만: 장점 재방문 주기가 짧아 효과를 빨리 볼 수 있다. 주제 이름과 일치한다 / 단점 회전율이 높아 사장님이 시간을 내기 어렵다
  - 예약 기반 뷰티: 장점 고객 데이터가 이미 쌓인다 / 단점 이번 조사 자료가 요식업 중심이다
  - 소상공인 전체: 장점 시장이 넓어 보인다 / 단점 세그먼트마다 다른 제품이 되어 검증이 어렵다
- **상태**: 확정 (문채원, 2026-10-20)
- **선택**: 요식업만
- **이유**: 같은 가설도 세그먼트에 따라 다른 제품이 되므로(E-03), 하나를 잡아야 인터뷰 10명으로 판단할 수 있다. 요식업 안에서도 업종 구성이 한식·커피 전문점·주점 등으로 크게 갈린다는 자료(E-15, 출처 확인 전)가 있어, 인터뷰 대상 업종은 T-05 에서 더 좁힐지 정한다.
- **근거**: E-03(2차 자료), E-01(2차 자료), E-15(검색 요약만 봄), E-06(원문 확인)

## D-02 도구를 주는 방식이 아니라 대신 해 주는 실행형으로 간다 — 확정

- **배경**: 경쟁 서비스 대부분이 도구와 대시보드를 주고 사장님이 쓰기를 기대한다(E-01). 국내외 사례 분석은 대행형 흐름과, 자동 발행 비율 50% 미만이면 대행 모델로 전환하라는 기준을 제시한다(E-02).
- **선택지**
  - 도구형: 장점 만들기 쉽다 / 단점 사장님이 시간이 없어 방치한다(P-01)
  - 실행형(할 일 1개 + 문구 완성): 장점 방치 원인인 시간·판단을 직접 줄인다 / 단점 효과가 사용자의 실행에 달려 있다
  - 사람이 대신 하는 대행형: 장점 실행률이 가장 높을 수 있다 / 단점 사람 시간이 들어 확장이 어렵다
- **상태**: 확정 (문채원, 2026-10-20)
- **선택**: 실행형. 수행률이 50% 미만이면 대행형 전환을 검토한다(K-02).
- **이유**: 문제 가설 P-01 과 P-03 이 맞다면 실행형이 가장 작은 해결안이다.
- **근거**: E-01(2차 자료), E-02(2차 자료)

## D-03 MVP 는 다섯 기능으로 한정한다 — 확정

- **배경**: 노션 기획안은 핵심 기능 6가지를 모두 담는다. 이 중 밈 설명과 원클릭 동시 발행은 검증되지 않은 가정에 기대고 있다(X-04, X-06).
- **선택지**
  - 6가지 전부: 장점 기획안과 같다 / 단점 밈 가치와 연동 가능 범위가 확인되지 않은 채 만들게 된다
  - 5개(등록, 문구, 할 일, 복사·공유, 실행 체크): 장점 가설 H-04 를 재는 데 필요한 최소 구성이다 / 단점 차별점으로 적은 밈 설명이 빠진다
  - 3개: 장점 가장 가볍다 / 단점 수행률을 재는 실행 체크가 빠지면 검증이 안 된다
- **상태**: 확정 (문채원, 2026-10-20)
- **선택**: 5개
- **이유**: 실행 체크(F-05)가 없으면 H-04 를 측정할 수 없고, 복사·공유(F-04)가 없으면 만든 문구가 쓰이지 못한다. 나머지는 가설이 지지될 때 추가한다.
- **근거**: E-04(2차 자료)

## D-04 검증은 인터뷰, 컨시어지, 랜딩·가격 순으로 한다 — 확정

- **배경**: 노션의 검증 틀(E-05)은 인터뷰와 가짜 문 랜딩을 제안하고, 문제 분해 문서(E-03)는 행동 기반 질문을 제안한다.
- **선택지**
  - 바로 개발: 장점 결과물이 빨리 나온다 / 단점 문제가 없다면 전부 낭비다
  - 인터뷰 → 컨시어지 → 랜딩·가격: 장점 비용이 적은 것부터 확인한다 / 단점 시간이 걸린다
- **상태**: 확정 (문채원, 2026-10-20)
- **선택**: 인터뷰 → 컨시어지 → 랜딩·가격
- **이유**: 코드를 쓰기 전에 문제(T-01)와 실행률(T-02)을 먼저 확인한다.
- **근거**: E-03(2차 자료), E-05(2차 자료)

## D-05 가격 시안은 검증 전 값으로만 쓴다 — 확정

- **배경**: 노션 기획안의 가격은 무료 / 월 19,000원 / 월 39,000원이다(E-04). 경쟁사 요금은 아직 확인하지 못했다(E-10).
- **선택지**
  - 시안을 확정가로 사용: 장점 문서가 단순해진다 / 단점 근거가 없다
  - 시안으로 두고 행동 기반 가격 테스트로 확인: 장점 근거 위에서 정한다 / 단점 확정이 늦어진다
- **상태**: 확정 (문채원, 2026-10-20)
- **선택**: 시안으로 두고 T-02, T-03 에서 확인한다
- **이유**: '월 3만 원이면 쓰시겠어요'가 아니라 '지금 당장 시작하시겠어요'로 묻는다(E-03).
- **근거**: E-03(2차 자료), E-04(2차 자료)

## D-06 MVP 에서는 자동 발행 대신 복사·공유로 시작한다 — 확정

- **배경**: 채널 연동 가능 범위와 정책을 확인하지 못했고(X-04), 자동 생성 콘텐츠는 승인 단계에서 방치될 수 있다(E-02).
- **선택지**
  - 자동 동시 발행: 장점 사장님 수고가 가장 적다 / 단점 연동 범위가 불확실하고, 잘못 올라가면 되돌리기 어렵다
  - 복사·공유 보조: 장점 바로 만들 수 있고 사장님이 마지막 확인을 한다 / 단점 사장님이 직접 올려야 한다
- **상태**: 확정 (문채원, 2026-10-20)
- **선택**: 복사·공유 보조
- **이유**: 자동 발행(F-07)은 T-04 로 연동 범위를 확인한 뒤 결정한다.
- **근거**: E-02(2차 자료)

## D-07 이번 프로젝트는 출시가 아니라 기획과 검증까지로 한정한다 — 확정

- **배경**: 학생 개인이 유료 서비스를 운영할 때의 사업자 등록·약관·개인정보 책임을 아직 확인하지 못했다(X-08).
- **선택지**
  - 실제 유료 출시: 장점 가장 현실적인 검증이다 / 단점 확인하지 못한 책임이 생긴다
  - 기획과 검증(인터뷰, 컨시어지, 랜딩)까지: 장점 포트폴리오에 필요한 산출물과 근거를 얻는다 / 단점 실제 결제 데이터는 얻지 못한다
- **상태**: 확정 (문채원, 2026-10-20)
- **선택**: 기획과 검증까지
- **이유**: 문제가 실제로 있는지와 실행형이 통하는지는 출시 없이도 확인할 수 있다(T-01, T-02).
- **근거**: 판단: 확인하지 못한 법적·운영 책임을 지지 않는 쪽을 택한다

## D-08 포트폴리오에는 확인된 것만 사실처럼 쓴다 — 확정

- **배경**: 지금 모든 문제는 가설이고, 근거는 2차 자료와 검색 요약뿐이다.
- **선택지**
  - 완성된 서비스처럼 서술: 장점 보기 좋다 / 단점 확인하지 않은 것을 사실처럼 말하게 된다
  - 문제, 가설, 설계, 검증 계획으로 서술하고 결과가 생기면 추가: 장점 정직하고 과정이 드러난다 / 단점 결과 수치가 없다
- **상태**: 확정 (문채원, 2026-10-20)
- **선택**: 문제, 가설, 설계, 검증 계획으로 서술한다
- **이유**: validated 문제는 verified 근거가 있을 때만 쓰도록 하네스가 막는다(EVD-03).
- **근거**: 판단: 포트폴리오의 신뢰는 확인한 범위와 못한 범위를 구분하는 데서 나온다
